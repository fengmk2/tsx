# Configuration

The standalone transform API reads configuration through oxc-node's resolver; it does not accept compiler options per call. Automatic discovery selects an ancestor config that claims the file through its program-membership rules. An explicitly selected config applies to every file. Resolution has additional fallbacks that do not apply to emitted code ([configuration ownership](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L130-L233)).

`setTsconfigPath` must run before the first transformation or resolution. Observed with npm `1.0.1`, calling it after `OxcTransformer.transform` throws `setTsconfigPath() must be called before the first transform or resolve` ([API contract](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/packages/core/index.d.ts#L177-L205)). A transformer's `cwd` is not an independent per-instance compiler configuration.

The JSX default is the automatic production runtime. `jsx: "react"` selects classic JSX; `react-jsxdev` selects the automatic development runtime. Unset values, `preserve`, and `react-native` use automatic production JSX ([mapping](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L2006-L2021), [option construction](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L2400-L2424)). Observed without a config, `<div>hello</div>` introduces `require("react/jsx-runtime")` in standalone output.

Source language comes from the filename; the public API has no explicit language override ([classification](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L2088-L2097), [parser setup](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L2268-L2278)). Observed with `query.ts?ns=one`, a TypeScript annotation fails JavaScript parsing. Callers must distinguish source identity from a path used for language selection.

Helper output defaults to bare `@oxc-node/core/helpers/*` specifiers. A standalone caller can replace the module prefix through the constructor ([helper options](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/src/lib.rs#L2467-L2478)). The registered loader solves helper ownership separately: it tags helpers per installed copy and resolves them against that copy, including for source files outside the package's resolution scope ([registration and resolution](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/packages/core/register.mjs#L51-L151)). Merely importing `OxcTransformer` does not install those resolution hooks.
