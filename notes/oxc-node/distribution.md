# Distribution

The published npm `@oxc-node/core@1.0.1` manifest has no `engines` declaration. It lists 16 native optional packages covering selected Android, macOS, Linux, Windows, FreeBSD, and OpenHarmony targets ([published package metadata](https://registry.npmjs.org/@oxc-node%2Fcore/1.0.1), [source targets](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/packages/core/package.json#L1136-L1155)). A manifest without an engine restriction is not evidence that every loader entry supports old Node releases.

Observed on macOS arm64 with Node `18.0.0`, importing the native API and transforming `const value: number = 42` succeeds. Importing `register.mjs` fails with `TypeError: register is not a function`. Registration uses `module.registerHooks` only on Node `26.2.0` or later and otherwise calls `module.register` ([runtime gate](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/packages/core/register.mjs#L325-L388)). The runtime requirements of the native transformer and complete registered loader are therefore separate.

The generated binding loader can try a local WASI artifact or `@oxc-node/core-wasm32-wasi` when native loading fails ([fallback](https://github.com/oxc-project/oxc-node/blob/6d5376df15df5446a91d01d53f3d7965d8b9708e/packages/core/index.js#L580-L713)). However, the published core manifest does not list that WASI package as an optional dependency, and the core tarball has no local WASI artifact. Observed after an ordinary installation on macOS, `NAPI_RS_FORCE_WASI=error` fails with `WASI binding not found and NAPI_RS_FORCE_WASI is set to error`. The separate WASI package exists at version `1.0.1`; it is not an automatically installed fallback in this release.
